What `tier-one` covers:

- **Geometry.** Light and dark at 375, 768 and 1280 px, on every size rung:
  - each chart is its rung's height: bar and pie 160/240/384 px, sparkline
    20/32/64 px;
  - nothing leaves the plot or the page;
  - a gap draws no bar;
  - the metric's value stays on one line.
- **Contrast against the page.** Bars, slices and the sparkline line are
  4.48–4.49:1 in light and 5.96–5.98:1 in dark. The series and the parts
  differ.
- **Keyboard and screen reader:**
  - Bar chart: Tab reaches the plot after the legend. The cursor is said
    («Москва, II квартал: 465») and Enter chooses. On a horizontal chart, Down
    walks the bars. `table="hidden"` keeps every row.
  - Pie chart: the cursor says the share and the value («Телефон: 3 % (30)»).
    The summary says the whole («Частей: 4, всего 1 000. …»).
  - Sparkline: an image named by its data, with no Tab stop.
  - Metric: an `openable` tile is one button, and Enter and Space open it. The
    change says its direction in words («▼ снижение −30 %»).
- **Motion and colours.** Under reduced motion there is no transition. In
  forced colours the bar series differ by fill and dash. The slices are
  outlines that keep their shares.
- **Load.** 1,000 stacked categories (2,000 bars) at 4× CPU throttling draw
  first in 53 ms.

The dashboard page was opened in the browser through the Loader. Every chart
rendered, there were no console errors, and the late tile loaded.

## Larena's metric tile (parameters.md §15)

| Need | Where it is in `sf-metric` |
|---|---|
| A value with a unit | `value`, `format` (`unit-gigabyte`, `percent`, `currency-RUB`, …) |
| A limit drawn as a meter | `max`, `limit-text`: role `meter` with the value text; the bar is `sf-progress-bar`, hidden from the tree |
| Change against a previous period | `previous` or `delta`, `delta-format`, `period-text`; an arrow and a word, not colour alone |
| The meaning of a change | `better` `up`, `down` or `none` |
| A status tone with a hint | `status` in the shared vocabulary, `hint`; the page states it, nothing is inferred |
| Skeleton | `data-state="loading"` keeps the tile's size |
| A link or a press | `href`, or `openable` with `sf-metric-open`; one target, no nested controls |
| A chart inside | the `chart` slot (an `sf-sparkline`) |
| Rows and grids on a phone | a fluid tile with `--sf-metric-min-inline-size`; the value line never wraps |

## Not done in M1

- **`stack` on `sf-line-chart` (stacked areas).** D1 names it as a line
  setting. It was not in M1; it is built in the line chart 0.2.0
  (`docs/evidence/line-chart-0.2.0.md`).
- **The chart slot only accepts any content.** `sf-metric` takes plain slot
  content (§4.5). A slot that `accepts` only charts needs a `chart@1`
  interface (§4.5.1, §20).
- **Canvas past 2,000 marks.** No chart is built with Canvas yet. A bar
  chart past a few hundred categories is a line chart's case, so Canvas waits
  for scatter (Tier 2). This is recorded in the bar chart's `x-decisions`.

## Framework parts needed

The seven parts of the M0 evidence still hold. The dispatcher took them as
one order and keeps the pin until that pair arrives. M1 adds two:

1. **The status gate and the package.** `sf-metric` uses the shared status
   vocabulary as the canonical `status` from the start. The free
   `contracts/public-api-axes.json` does not list package components, so it
   is not registered there. A place for package entries would let the gate
   hold it.
2. **A package shared module.** All five charts would then load one chart
   core instead of bundling it five times.
